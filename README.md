# UVmapping Blender

참조 이미지와 한 줄 프롬프트로 AI 3면도를 생성하고, 이미 펼쳐 둔 UV에 손맵 텍스처를 베이크하는 Blender Extension입니다. UV 언랩은 Blender 기본 도구를 사용하고, 이 애드온은 텍스처링만 담당합니다.

## 요구 사항

- Blender 4.5 LTS 이상
- 편집 가능한 Mesh 객체와 **0-1 안에 배치된 UV 맵**
- OpenRouter API 키 하나와 Blender의 Online Access 허용

## 설치

1. Blender에서 `Edit > Preferences > Get Extensions`를 엽니다.
2. 오른쪽 위 메뉴에서 `Repositories > Add Remote Repository`를 선택합니다.
3. 저장소 URL에 다음 주소를 입력합니다.

   ```text
   https://zzamjak-cloud.github.io/UVmapping-Blender/index.json
   ```

4. 저장소 목록에서 이름을 `UVmapping-Blender`로 바꿉니다. Blender는 원격 저장소 이름을 URL의 **호스트**에서 자동으로 정하므로, 같은 호스트에 있는 다른 저장소를 함께 쓰면 `zzamjak-cloud.github.io.001`처럼 구분이 안 되는 이름이 붙습니다. 목록의 이름을 더블클릭해 바꾸면 환경설정에 그대로 저장됩니다.
5. `Refresh Remote`를 실행한 뒤 `UV Mapping Blender`를 검색합니다.
6. `Install`을 눌러 설치하고 Extension을 활성화합니다.

같은 URL을 두 번 등록하면 저장소가 두 개 만들어져 `Get Extensions`에 같은 애드온이 두 번 보입니다. 이때는 `Repositories`에서 중복된 항목 하나를 `−`로 지우면 됩니다.

### 업데이트 확인

Blender의 Extension 저장소를 새로 고치면 사용 가능한 업데이트를 확인할 수 있습니다. `Check for Updates on Startup`을 켜면 Blender를 시작할 때 새 버전을 확인해 알려줍니다. 업데이트는 사용자가 승인해야 하며 무인으로 자동 설치되지 않습니다.

## 사용법

### 준비: UV 펼치기

이 애드온은 UV를 만들지 않습니다. Blender 기본 도구로 UV를 먼저 준비합니다.

1. `UV Editing` 워크스페이스에서 Seam을 표시하고 `U > Unwrap`(또는 `Smart UV Project`)으로 UV를 만듭니다.
2. `UV > Pack Islands`로 모든 UV를 0-1 안에 배치합니다.
3. 여러 객체를 한 장의 텍스처에 함께 구울 때는 객체들의 UV가 **서로 겹치지 않아야** 합니다. 겹치면 3면도 생성 단계에서 막고 안내합니다.
4. UV가 없거나 0-1을 벗어나면 패널에 경고가 표시되고 생성이 중단됩니다.

### AI 손맵 텍스처 디자인

패널은 대상 → 참조·지시 → 품질/모델 → `텍스처 생성` 버튼 순의 기본 화면 하나로 시작합니다. 세부 옵션은 `고급 설정` 접힘 안에, 그중 전문가용 값은 다시 `전문가 설정` 하위 접힘 안에 있습니다. 온라인 접근 차단, OpenRouter API 키 미입력, UV 맵 누락은 문제가 있을 때만 경고 상자로 표시됩니다.

1. 텍스처를 만들 Mesh 객체를 선택하고 `3D Viewport > Sidebar(N) > UV Mapping`에서 `AI 손맵 텍스처` 패널을 엽니다.
2. `Edit > Preferences > Add-ons > UV Mapping Blender`에서 [openrouter.ai/keys](https://openrouter.ai/keys)에서 발급한 **OpenRouter API 키 하나**를 입력합니다. 분석과 이미지 생성 모두 이 키 하나로 처리됩니다. 키는 프로젝트나 `.blend`가 아닌 Blender 개인 환경설정에 저장되고 입력창에서는 가려지지만, OS Keychain 암호화 저장소는 아닙니다. 공유 PC에서는 환경 변수 `OPENROUTER_API_KEY` 사용을 권장합니다. 업데이트나 재설치 중 Blender가 애드온 환경설정을 지워도 키가 사라지지 않도록, 입력한 키를 Blender 사용자 설정 폴더의 `config/uvmapping_blender/openrouter_api_key`에도 백업해 두고 키 칸이 비어 있으면 자동으로 복구합니다. 이 백업은 애드온을 제거해도 남으므로, 완전히 지우려면 키 칸을 비우세요.
3. `대상 객체`에서 `선택 객체 등록`을 누르면 그 객체들만 대상이 됩니다. 등록이 없으면 "선택한 Mesh N개를 대상으로 합니다" 한 줄과 함께 현재 선택을 그대로 씁니다. Edit·Paint 모드에서 실행하면 Object Mode로 자동 전환합니다.
4. `스타일 참조와 지시`에서 Pinterest 등에서 저장한 JPG, PNG, WebP 참조 이미지를 최대 5장 추가합니다(macOS·Windows는 브라우저 `이미지 복사` 후 `클립보드` 버튼으로 붙여넣기 가능). 참조 이미지는 기본적으로 **분석 단계에서만** 쓰여 3면도 생성 호출에는 모델 형상 contact sheet만 보내므로, 이미지 모델이 참조 캐릭터 형상을 그대로 복제하지 않습니다. 참조에 없는 요구는 그 아래 지시 칸에 한 문장으로 적고, 한글 조합이 불안정하면 `한글 프롬프트 입력` 버튼으로 OS 입력창을 씁니다. 참조와 지시 중 하나만 있어도 생성할 수 있습니다.
5. `품질과 모델`에서 `품질` 프리셋 하나를 고릅니다.

   | 프리셋 | 시점 구성 | 생성 이미지 크기 | 텍스처 크기 | 다시 그리기 | 적용 후 검증 | 호출 수 |
   |---|---|---|---|---|---|---|
   | 빠름 | 3면도 | 자동 | 1024 | 끔 | 끔 | 1회 |
   | 표준(기본값) | 6면도 | 자동 | 1024 | 1회 | 켬 | 1회(+재생성) |
   | 고품질 | QUAD(6면 4캔버스) | 자동 | 2048 | 1회 | 켬 | 4회(+재생성) |
   | 사용자 지정 | 고급 설정에서 고른 값을 그대로 씁니다 | | | | | |

   `고급 설정`에서 시점 구성·생성 이미지 크기·텍스처 크기·다시 그리기 횟수·적용 후 검증 중 하나라도 직접 바꾸면 `품질`은 자동으로 `사용자 지정`으로 바뀝니다. 시점 구성의 차이는 3면도(FRONT/RIGHT/BACK 21:9 1회)·6면도(3×2 격자 3:2, 상·하·좌 시점도 실제 그림으로 받아 투영, 1회)·QUAD(정면·뒷면·좌우·상하를 캔버스 4장으로 나눠 2라운드 4회 호출)입니다. 캔버스 한 장에 담는 시점이 적을수록 시점당 픽셀 수가 커지는 경향이 있지만 정확한 배수는 실측 전이라 단정하지 않습니다.
6. 같은 상자의 `모델 프리셋`에서 분석·생성 모델 조합을 고릅니다. 바꾸면 분석 모델과 이미지 생성 모델이 함께 전환됩니다.

   | 프리셋 | 분석 모델 | 이미지 생성 모델 | 비고 |
   |---|---|---|---|
   | Nano Banana Pro(기본값) | `google/gemini-3.7-flash` | `google/gemini-3-pro-image` | 생성 이미지 크기(1K/2K/4K)를 그대로 씁니다 |
   | GPT Image(덕테이프) | `openai/gpt-5.6-sol` | `openai/gpt-5.4-image-2` | 품질 단계(medium/high) 사용, 1K 고정 |
   | GPT Image 2.5 Sunburst(정밀, 느리고 비쌈 · 덕테이프 2.5 선버스트) | `openai/gpt-5.6-sol` | `openai/gpt-image-2.5-sunburst` | 품질 단계(medium/high/xhigh) 사용, 1K 고정 |
   | GPT Image 2.5 Flare(속도 우선 · 덕테이프 2.5 플레어) | `openai/gpt-5.6-sol` | `openai/gpt-image-2.5-flare` | 품질 단계(medium/high/xhigh) 사용, 1K 고정 |

   GPT 계열 모델은 `resolution` 파라미터를 받지 않아 결과 이미지가 종횡비로 1K급에 고정되며, `품질` 프리셋이 정하거나 고급 설정의 `품질 단계`에서 직접 고른 등급(medium/high/xhigh)이 대신 전달됩니다. 모델이 그 등급을 받지 못하면(예: 일반 GPT Image에 xhigh) 자동으로 한 단계씩 낮춰 보냅니다. StyleStudio 프로젝트에서 2.5 Sunburst를 기본값으로 올렸다가 타일맵 변형에서 재질 스케일 문제가 확인돼 되돌린 이력이 있어, 이 애드온의 기본값도 Nano Banana Pro로 유지합니다.
7. `텍스처 생성`(연산자 이름은 이전과 같은 `단일 다면도 생성`이며 F6 Redo 패널·검색에 그 이름으로 나타납니다)을 누르면 참조 분석이 없거나 참조가 바뀌었을 때 분석을 먼저 실행하고, 이어서 다면도 생성을, `생성 후 자동 적용`(고급 설정, 기본 켬)이 켜져 있으면 Diffuse 적용까지 한 번에 이어갑니다. 자동 적용이 꺼져 있거나 적용을 기다리는 결과가 있으면 `Diffuse 적용` 버튼이 대신 표시됩니다. 순차 생성이 중단되면 `생성 상태 초기화` 버튼이 나타납니다.
8. `적용 후 검증`(기본 켬)이 켜져 있으면 적용 직후 텍스처를 입힌 모델을 각 시점에서 다시 렌더해 생성 그림과 비교합니다. 패널의 `검증` 상자에 시점별 점수(0~1, 0.6 미만은 미달)와 실루엣 불일치 시점이 표시되고, `검증 시트 열기`로 가이드 / 생성 그림 / 베이크 렌더를 시점별로 나란히 놓은 `*_verify.png`를 열 수 있습니다. 점수 미달이나 불일치가 있으면 `재생성 권장`이 표시됩니다. 이 단계는 로컬 처리라 비용이 없습니다.

`고급 설정`에는 시점 구성, 생성 이미지 크기(또는 GPT 계열의 품질 단계), 생성 방식(`한 번 호출` 기본값 / `순차 인페인팅 · 시점 수만큼 호출`), 형태가 어긋나면 다시 그리기(횟수), 텍스처 크기, UV 패딩, 생성 후 자동 적용, 적용 후 검증, 참조가 있을 때는 생성에도 참조 이미지 전달과 `참조 이미지 분석` 버튼이 있습니다. 순차 인페인팅은 OpenRouter 호출이 시점 수만큼(3면도 3회, 6면도 6회) 발생해 비용 경고가 표시됩니다. 그 안의 `전문가 설정`에는 투영 블렌딩의 시점 전이 폭, `시점 경계 선명하게`(기본 켬, 픽셀마다 가장 정면으로 보이는 시점 하나를 쓰고 경계 띠에서만 섞어 이중상을 줄임), `경계 혼합 폭(도)`(기본 12, 범위 4~30, 좁을수록 경계가 선명하고 넓을수록 전이가 부드러움, 앞의 항목이 켜져 있을 때만 조절 가능), 시점 간 색조 보정·실루엣 정합(행 워프, 기본 꺼짐)과, 분석·이미지 생성 모델 슬러그를 [openrouter.ai/models](https://openrouter.ai/models)에서 직접 입력하는 칸이 있습니다.

Subdivision, Mirror, Bevel처럼 topology를 바꾸는 Modifier가 있어도 평가 결과를 그대로 투영합니다. 다만 Mirror나 Array의 UV Offset처럼 UV를 0-1 밖으로 보내는 설정은 해당 면이 비어 경고가 표시됩니다.

현재 CPU 베이크는 최대 4096×4096(`텍스처 크기` 선택지의 상한)을 지원하며 기본값은 1024×1024입니다. `텍스처 크기`와 `UV 패딩`은 `.blend`에 저장되므로, 이전에 저장한 파일은 그때 값이 그대로 유지됩니다. 3면도 구성에서는 직접 보이지 않는 상·하면을 인접 시점의 색을 확장해 채우므로, 의미 있는 상면 그림이 필요한 에셋은 6면도 또는 QUAD 구성을 사용합니다. 다면도 생성 시점과 베이크 시점에 각각 현재 UV로 계약을 다시 계산해 비교하므로, 모델 Transform, 메시 또는 UV가 그 사이에 바뀌면 잘못 투영하지 않고 재생성을 안내합니다.

### 매핑 파츠 등록

A포즈의 팔처럼 다른 부위를 가리는 파츠를 나눠 두면, 아래 `파츠 분해도 생성`으로 파츠를 서로 가리지 않게 벌려 놓은 채 생성·투영합니다. 파츠는 Vertex Group이 아니라 **면 단위**로 등록합니다.

1. 대상 Mesh를 활성 객체로 두고 `AI 손맵 텍스처 > 매핑 파츠` 하위 패널을 엽니다.
2. Edit Mode에서 파츠로 묶을 면을 선택하고 `+`를 누릅니다. 대화상자의 `종류`에는 아직 등록하지 않은 다음 기본 부위(머리 → 몸통 → 왼팔 → 오른팔 → 왼손 → 오른손 → 왼다리 → 오른다리 → 왼발 → 오른발)가 미리 골라져 있어, 면을 고르고 Enter만 눌러도 차례대로 등록됩니다.
3. 기본 부위가 아닌 파츠(꼬리, 날개, 모자 등)는 `종류`에서 `직접 입력`을 고르고 이름을 적습니다. 이름에 `팔`·`arm`·`허벅지`·`foot`처럼 매칭 단어와 `왼`·`오른`·`좌측`·`우측`·`L`·`R`·`Left`·`Right` 같은 좌우 표기가 있으면 해당 기본 부위로 자동 인식합니다. 영어는 단어 단위로만 인식해 `Surface`·`Leg Warmer`가 머리·팔로 오인되지 않고, `Armor`·`Hair`처럼 부위가 아닌 단어는 건너뜁니다(`Chest Armor`는 몸통). 목록에서 이름을 고쳐도 같은 규칙으로 종류가 따라 바뀌며, 목록에서 종류를 직접 고른 파츠는 이름을 바꿔도 종류가 유지됩니다. 좌우는 **캐릭터 기준**이라, 정면에서 볼 때 화면 오른쪽에 있는 팔이 왼팔입니다.
4. `다른 파츠에서 빼기`(기본 켬)가 켜져 있으면 선택한 면이 이미 다른 파츠에 있을 때 그 파츠에서 빠집니다. 면 하나가 한 파츠에만 속하게 유지하는 것을 권장합니다.
5. 목록 아래 `교체`·`추가`·`제거`로 활성 파츠의 면을 고치고, `면 선택`으로 활성 파츠 면을 Edit Mode에서 확인합니다.
6. 목록의 눈 아이콘으로 파츠 하나만 보이게(Isolate) 하고, 같은 아이콘이나 `전체 표시`로 되돌립니다. Isolate 전에 직접 숨겨 둔 면은 전체 표시 때 다시 숨겨집니다. 숨김은 Edit Mode와 Paint 모드 뷰포트에서 보입니다.
7. Object Mode에서는 패널 아래에 파츠 없는 면, 두 파츠 이상에 속한 면, 면이 없는 파츠, 같은 종류 중복 등록이 표시됩니다.

파츠 정보는 Mesh 데이터에 저장되어 `.blend`와 함께 보존되며, 파츠마다 `uvmapping_part_<고유값>` 면 속성이 생깁니다. 파츠를 지우면 그 속성도 함께 지워지고, Ctrl+Z로 되돌리면 이름·종류와 함께 목록에 다시 나타납니다. 다른 객체를 Ctrl+J로 합쳐 들어온 파츠 속성은 사용자 지정 파츠로 목록에 올라옵니다.

### 파츠 분해도 생성

전신 다면도는 팔에 가린 옆구리·겨드랑이, 서로 가린 다리 안쪽을 어떤 시점에서도 보지 못해 주변 색을 늘려 채웁니다. `매핑 파츠` 하위 패널의 `파츠 분해도 생성`(기본 켬)이 켜져 있고 등록 파츠가 있으면, 다면도를 다음처럼 **한 번의 호출로** 생성합니다.

1. 시점마다 파츠 실루엣이 서로 겹치는지 계산해, 겹치는 파츠만 화면 평면 안에서 옆으로 벌립니다. 정면·측면·뒷면에서 가로로만 옮겨 높이가 그대로라 벨트·소매 끝 같은 둘레 무늬가 시점 사이에서 같은 높이로 이어집니다. 위·아래 시점은 벌리면 팔다리 단면만 늘어서 AI가 알아보지 못하므로 원래 자세 그대로 둡니다. 원래 자세에서 이미 떨어져 있던 파츠(정면의 두 다리 등)는 그대로 둡니다.
2. 손·발처럼 이어진 하위 파츠는 팔·다리와 한 덩어리로 움직여 떨어져 나가지 않습니다. 손목·발목처럼 연결부가 조금 겹치는 것은 그대로 두고, 측면의 팔처럼 몸통을 크게 가리는 경우만 옮깁니다.
3. 벌린 배치로 형상 가이드를 렌더하고(잘린 단면 안쪽은 그리지 않음), 프롬프트에 "부위를 벌려 놓은 분해도이니 조각을 붙이지 말고 제자리에서 칠하되 경계 무늬는 이어 그리라"는 계약을 덧붙입니다.
4. 베이크·실루엣 검사·적용 후 검증은 같은 배치로 파츠를 옮겨 투영하므로, 옆구리·팔 안쪽·다리 안쪽도 생성 그림의 실제 색을 받습니다.

- OpenRouter 호출 수는 늘지 않습니다. 측면처럼 파츠를 많이 벌린 시점은 캔버스 안에서 모델이 조금 작아집니다.
- 어느 파츠에도 등록하지 않은 면(예: 빠뜨린 발바닥)은 정점으로 이어진 파츠에 붙어 함께 움직입니다. 어떤 파츠와도 이어지지 않은 조각은 따로 배치됩니다.
- 파츠가 없는 객체(예: 따로 둔 모자)는 나누지 않고 제자리에 둡니다.
- 생성 뒤 파츠 면을 바꾸면 옮길 양이 맞지 않아 `Diffuse 다시 적용`이 거부됩니다. 다시 생성하세요.
- 파츠를 등록해 두고 이 옵션을 끄면 패널에 경고가 표시되고, 원래 자세 그대로 생성합니다.

### 부위별 순차 생성

`생성 방식`을 `부위별 순차`로 고르면, 등록 파츠를 **머리·몸통**과 **팔·다리**(손·발 포함) 두 그룹으로 묶어 최대 2회 호출로 생성합니다.

1. 그룹마다 그 그룹 면만 남긴 임시 객체를 만들어 6면도 가이드를 렌더합니다. 다른 그룹이 없으므로 그룹 사이 가림이 없고, 부위가 화면을 크게 채웁니다. 측면에서 겹치는 좌우 팔·다리는 분해도로 벌립니다.
2. 머리·몸통을 먼저 생성합니다. 머리를 몸통과 한 장에 그려야 둥근 머리의 앞뒤를 몸통 방향으로 알아볼 수 있습니다.
3. 팔·다리는 머리·몸통 결과를 두 번째 입력 이미지로 붙여 팔레트와 어깨·골반 연결부 색을 맞춥니다.
4. 베이크는 그룹마다 그 부위 면만 그 그룹 그림으로 투영해 한 Atlas로 합칩니다. 시점 간 띠 높이 맞춤도 그룹마다 적용됩니다.

- 매핑 파츠를 먼저 등록해야 합니다. 사용자 지정 파츠와 등록하지 않은 면은 이어진 그룹을 따릅니다.
- 부위 그림은 그룹마다 따로라 적용 후 전신 렌더 검증은 하지 않습니다.
- 그룹마다 1024px로 굽고 띠 높이를 맞추므로 적용이 전신 1회보다 오래 걸립니다.
- 원하는 디자인을 유지하려면 그 디자인 이미지를 참조로 등록하세요. 프롬프트만 쓰면 생성할 때마다 디자인이 새로 정해집니다.

### 시점 간 띠 높이 맞춤

투영 베이크는 정면·측면·뒷면 그림을 각자 높이 그대로 모델에 입히므로, AI가 시점마다 벨트를 조금 다른 높이에 그리면 옆구리에서 단차가 납니다. 전문가 설정의 `시점 간 띠 높이 맞춤`(기본 켬)은 이웃한 두 시점이 함께 보는 표면에서 두 그림의 색이 정확히 겹치는 수직 어긋남을 파츠마다 찾아, 측면·뒷면을 그만큼 옮겨 읽습니다. 색을 섞거나 흐리지 않습니다. 시점마다 디자인 요소가 아예 다르게 그려진 경우(한쪽에만 있는 띠)는 맞출 수 없습니다.

## 문제 해결

생성이 실패하면 패널 상태 상자 아래에 실패 분류와 `실패 원인 보기` 버튼이 나타나고, 창이 열려 있으면 같은 내용이 팝업으로도 뜹니다. 팝업의 `원문 복사`는 영문 원문 전체를 클립보드에 넣습니다.

- **요청이 거부되는 경우**: `Your request was rejected as a result of our safety system` 같은 400 응답은 모델 제공사의 안전 시스템이 막은 것입니다. 유명 캐릭터·브랜드·실존 인물 이름을 프롬프트에서 빼고 외형(복장·색·비율·분위기)으로만 묘사하고, 공식 아트 대신 직접 그린 원화를 참조로 쓰세요. 모델을 바꿔도 같은 입력이면 다시 막힐 수 있습니다. 제공사에 문의할 때는 팝업에 표시된 요청 ID(`req_…`)를 첨부합니다.
- **이미지 없이 글만 돌아오는 경우**: 정책 거부가 완곡하게 나타난 형태입니다. 오류 메시지에 모델이 남긴 사유가 함께 실리므로 그 문장을 보고 프롬프트를 고치세요.
- **API 키 인증 실패(401/403)**: 환경 설정의 OpenRouter API 키를 다시 입력하고, 앞뒤 공백과 모델 사용 권한을 확인하세요.
- **요청 한도(429)**: 잠시 뒤 다시 시도하거나 품질 프리셋을 낮춰 한 번에 보내는 호출 수를 줄이세요.
- **네트워크 연결 실패**: 인터넷 연결과 프록시·VPN, Blender 환경 설정의 온라인 접근 허용 여부를 확인하세요.

## 릴리스 운영

`v*` 태그를 push하면 전체 회귀 검사와 공식 Blender Extension 빌드를 거쳐 GitHub Release 초안과 ZIP 자산까지만 생성합니다. 초안은 자동으로 공개하지 않습니다. 자산의 크기, SHA-256, 태그 대상 커밋을 `distribution/releases.lock.json`에 반영해 기본 브랜치에 push한 뒤 초안을 공개해야 합니다.

공개 이벤트는 보호된 Pages 환경에서 태그를 직접 배포하지 않고 기본 브랜치의 `workflow_dispatch`를 호출합니다. 배포 작업은 잠금 파일에 기록된 모든 공개 Release와 자산을 검증하지만, Blender 원격 저장소에는 SemVer상 최신 ZIP과 인덱스 항목 하나만 게시합니다. 따라서 과거 Release는 검증 가능한 이력으로 유지하면서도 동일 Extension ID의 중복 항목 때문에 업데이트가 이전 버전에 머무는 문제를 방지합니다.
